# GEOFUSION API Reference (Phase 2)

This document describes the Supabase/PostgREST API surface for GEOFUSION, including direct table endpoints, custom RPC functions, authentication procedures, and rate limiting.

## Authentication and Roles

The system uses three custom roles defined in the `profiles` table: `authenticated_viewer`, `researcher`, and `admin`.

**To obtain a JWT for local testing:**
1. Use Supabase Auth to create a user or sign in.
2. The user's role is stored in `public.profiles`. The default role upon signup is `authenticated_viewer`.
3. An admin or the `service_role` key must be used to elevate a user's role to `researcher` or `admin`.
4. The JWT returned by Supabase Auth must be included in the `Authorization` header as a Bearer token:
   `Authorization: Bearer <YOUR_JWT>`

## RPC Functions

Base URL for RPCs: `<SUPABASE_URL>/rest/v1/rpc/`

### 1. `get_risk_heatmap`
Returns the risk heatmap (geometries and prediction scores) for a given region and date.
- **Access**: Public (Anon + Auth).
- **Behavior**: Uses the active model by default. Because `models` is restricted, this function runs as `security definer` internally to resolve the active model ID, while safely joining only public `predictions` and `grid_cells`.

**Parameters (JSON Body):**
- `p_region` (string, required): The region name (e.g., "california").
- `p_date` (string/date, required): The prediction date (e.g., "2026-08-01").
- `p_model_id` (integer, optional): Force a specific model ID instead of the active one.

**Example Request:**
```bash
curl -X POST 'https://<PROJECT_REF>.supabase.co/rest/v1/rpc/get_risk_heatmap' \
-H "apikey: <ANON_KEY>" \
-H "Content-Type: application/json" \
-d '{"p_region": "california", "p_date": "2026-08-01"}'
```

### 2. `get_cell_timeseries`
Returns a merged timeseries of weather and prediction data for a single grid cell over a date range.
- **Access**: Public (Anon + Auth) can call it, but **weather columns will be returned as nulls** because the underlying `weather_series` table restricts access. `researcher` and `admin` roles will receive the full data.

**Parameters (JSON Body):**
- `p_grid_cell_id` (integer, required)
- `p_start` (string/date, required)
- `p_end` (string/date, required)

**Example Request:**
```bash
curl -X POST 'https://<PROJECT_REF>.supabase.co/rest/v1/rpc/get_cell_timeseries' \
-H "apikey: <ANON_KEY>" \
-H "Content-Type: application/json" \
-d '{"p_grid_cell_id": 1, "p_start": "2026-01-01", "p_end": "2026-12-31"}'
```

### 3. `get_active_model`
Returns the metadata for the currently active ML model.
- **Access**: `researcher`, `admin`, `service_role` only. Public callers will receive an empty result (0 rows).

**Example Request:**
```bash
curl -X POST 'https://<PROJECT_REF>.supabase.co/rest/v1/rpc/get_active_model' \
-H "apikey: <ANON_KEY>" \
-H "Authorization: Bearer <RESEARCHER_JWT>"
```

### 4. `get_pipeline_health`
Returns aggregate statistics for ETL pipeline runs over a time window.
- **Access**: `researcher`, `admin`, `service_role` only. Public callers will receive an empty result.

**Parameters (JSON Body):**
- `p_since` (string/timestamp, optional): The cutoff time. Defaults to 7 days ago.

**Example Request:**
```bash
curl -X POST 'https://<PROJECT_REF>.supabase.co/rest/v1/rpc/get_pipeline_health' \
-H "apikey: <ANON_KEY>" \
-H "Authorization: Bearer <ADMIN_JWT>" \
-d '{"p_since": "2026-08-01T00:00:00Z"}'
```

## Rate Limiting & Abuse Guardrails

Since Supabase does not currently offer granular, per-RPC rate limiting natively on the PostgREST layer:
- **Strategy**: We rely on Supabase's platform-level Edge Network rate limits (managed by Cloudflare) which protect against massive DDoS attacks. 
- **Future Scale**: Since this is a v1 pilot region deployment, strict business-logic rate limiting (e.g., X requests per user per minute) is deferred. If abuse is detected, the lightest viable mitigation is to deploy a Supabase Edge Function to proxy `get_risk_heatmap` and apply a distributed rate limit (e.g., using Upstash Redis) before forwarding the request to PostgREST.
